# ERRORS — 오류 사례집
> 목적: 오류를 증거→판단→수정→개선 확인의 사슬로 기록해, 같은 오류를 두 번 디버깅하지 않게 한다.
> 읽는 시점: 티켓 컨텍스트 작성 시(관련 키워드로 검색해 발췌 인라인). 비슷한 증상을 만났을 때. 재발 방지 승격을 판단할 때.
> 갱신 시점: 재작업·예상외 오류·디버깅 세션이 발생했을 때, 하위 에이전트 보고의 "④ 겪은 오류"가 채워져 왔을 때. 오류 없이 진행된 작업은 기록하지 않는다.

## E-001 · YYYY-MM-DD · (증상 한 줄)
- **증상**: 무엇이 어떻게 실패했나 (발생 티켓 T-###)
- **근거 데이터**: 판단의 근거가 된 로그·테스트 출력·재현 조건의 핵심 라인
- **판단**: 원인 + 그렇게 판단한 이유. 기각한 다른 가설이 있으면 기각 사유와 함께
- **수정**: 무엇을 어떻게 고쳤나
- **개선 확인**: 수정 후 무엇으로 개선을 확인했나 (테스트 결과·측정치 등 수정 전과 대비되는 데이터)
- **재발 방지**: 어디로 승격했나 (02 규약 / AGENTS 보정 / LESSONS / 없음)
